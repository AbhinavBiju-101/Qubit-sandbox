Constant, or balanced?

You're handed a hidden function f(x) that takes one bit and returns one bit, promised to be either constant (same output for every input) or balanced (outputs 0 for half the inputs, 1 for the other half). For a single-bit input there are only two inputs, so classically you might get lucky on 1 query — but in the worst case you need both queries to be sure.

The quantum trick: put the input in superposition, run the oracle once, and interference cancels out everything except the one bit of information you actually need — constant or balanced — in a single query, guaranteed, every time.

The oracle is wired as |x⟩|y⟩ → |x⟩|y ⊕ f(x)⟩ — the CNOT and X gates you already know from Two Qubits, just relabeled as "the unknown function" for this lesson.

Bonus: this scales

With n input bits, a classical worst case needs 2ⁿ⁻¹ + 1 queries to be certain — exponentially many. The quantum algorithm still needs exactly one, regardless of n. The 1-bit version here is the smallest case where that gap already exists; it just isn't dramatic yet at n=1.

4

Nobody runs this for a real problem — and that's the point

Be honest about what you just built: "is this specific contrived function constant or balanced" isn't a problem anyone actually has. Deutsch-Jozsa's real importance is historical and structural, not practical — published in 1992, it was the first algorithm to give a rigorous, provable case where a quantum computer needs exponentially fewer queries than any possible classical algorithm, for any input size. Before it, "quantum speedup" was a hope; after it, it was a theorem.

Every algorithm since has built on the same trick you just ran: superposition, an oracle, then interference to cancel out everything except the one bit of global information you actually wanted. Grover's Search (next lesson) and Shor's Algorithm (Module 6) are both, at their core, more sophisticated versions of exactly this pattern.
