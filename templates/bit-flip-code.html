MODULE 5 · ERROR CORRECTION & NOISE

Catch the error without looking at the data.

The simplest quantum error-correcting code: spread 1 logical qubit across 3 physical ones, and use 2 extra "syndrome" qubits to find a flipped bit — without ever measuring, and therefore destroying, the logical state itself. Five steps, including the truth table behind "which qubit flipped."

1

Why you can't just "check the bit"

Classical error correction can just look at a bit and see if it flipped. Measuring a qubit directly would collapse any superposition it's carrying — so quantum error correction has to detect that an error happened, and which qubit it hit, without ever learning the logical α or β. The trick: encode 1 logical qubit into 3 physical ones (α|0⟩+β|1⟩ → α|000⟩+β|111⟩, using two CNOTs — literally the entangling gate from Two Qubits, twice), then use two extra ancilla qubits to measure only the parity between pairs of data qubits, never the data qubits themselves.

Those two parity bits — the "syndrome" — pinpoint exactly which of the 3 qubits flipped (or that none did), and a single corrective X fixes it. The logical superposition was never touched. Step 2 works out exactly why two parity bits are enough to pin down one of four possibilities.

Phase-flip errors get corrected the same way, just rotated: apply H to all 3 qubits before and after the exact same bit-flip circuit, and a phase-flip error becomes a bit-flip error in the rotated basis. One trick, two error types.
2

Why two parity bits are enough to find one flipped qubit

Two parity checks are wired deliberately so they overlap: the first ancilla checks parity(qubit 0, qubit 1), the second checks parity(qubit 1, qubit 2) — qubit 1 sits in both checks, qubits 0 and 2 each sit in only one. A single bit-flip on any one data qubit flips exactly the parities that qubit participates in, and leaves the others alone. Work through all four cases:

Four possible syndromes, four possible situations (no error, or one of three specific qubits) — every case gets its own unique two-bit code, so reading the syndrome is enough to identify the exact fix with total certainty, the same way the sandbox's faultyQubit logic looks up this exact table. Two bits can distinguish at most four possibilities (2²=4), and there are exactly four possibilities here — the code is precisely large enough for the job, no wasted capacity, no gaps.

Bonus: this doesn't catch everything

This code corrects exactly one bit-flip error among the three qubits. Two simultaneous bit-flips would be misdiagnosed as a single flip on the third qubit and "corrected" the wrong way — which is exactly why real quantum computers stack multiple layers of these codes (and use many more physical qubits per logical one) rather than relying on this simplest version alone.

5

Surface codes: the 2D version that's actually deployed

The 5-qubit code above only protects against bit-flips. A real quantum computer needs protection against both bit-flip and phase-flip errors (and everything in between) simultaneously, arranged so every physical qubit is only ever wired to its nearest neighbors — matching how chips are actually fabricated (recall Hardware Lab's chip layout). The dominant real answer is the surface code: data qubits and syndrome-measurement qubits arranged in a 2D checkerboard grid, running the same core idea as this lesson's parity checks, just repeated in both directions and continuously in time rather than once.

There's a genuine threshold: if the per-gate physical error rate is below roughly 1%, adding more physical qubits per logical qubit (a "larger code distance") makes the logical error rate fall — error correction actually winning. Above that threshold, adding more qubits makes things worse instead. That threshold, and how close current hardware's real gate fidelities (NISQ, next lesson) sit to it, is one of the field's central open engineering problems right now.
